# bam v0.3 `bam run --revision` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `bam run PLAN --revision REV` (and a Revision row in the TUI run form) builds a chosen commit, and stops the build when Bamboo ignores the revision.

**Architecture:** `provider.TriggerRequest.Revision` travels to `provider/bamboo`, which sends `customRevision` in the queue query and reports an ignored revision as the queued build plus an error wrapping `errs.ErrUnsupported`. `app.Run` stops that build (retrying on the injected clock) and returns a bamboo-kind error. `app.PlanRef.Revision` carries the choice so `view` and the edit buffer render it without new parameters.

**Tech Stack:** Go, cobra, bubbletea, testify.

**Spec:** `docs/superpowers/specs/2026-09-24-bam-v0.3-run-revision-design.md`

## Global Constraints

- Package import rules of `CLAUDE.md` hold: `app` never prints or imports cobra; only `provider/bamboo` speaks Bamboo REST; the string `Custom revision build` appears only in `provider/bamboo`.
- No format check on the revision value anywhere; it goes to Bamboo exactly as given.
- `--json` fields are added, never renamed or removed: `RunDoc` gains `revision` (string, `""` when none).
- Exit codes: 2 for `--revision ""`, 5 for an ignored revision, 1 for a watched build that ends `not_built`.
- Placeholders only in code, tests, fixtures and docs: `bamboo.example.com`, `PROJ`, `jdoe`, SHAs like `abc1234…`.
- No new dependencies.
- Before each commit: `export PATH="$HOME/.local/go/bin:$HOME/go/bin:$PATH"`, `go test ./...` for the touched packages, `make lint`.
- Conventional Commits, owner identity only; no `Co-Authored-By`, `Claude-Session` or "Generated with" lines.

## Review Focus

1. **A revision with surrounding spaces or odd characters** (`" abc1234"`, `v1.2`, `main`): sent as given, URL-encoded by `url.Values`; no crash, no local rejection. Pinned in Task 1 (`TestTriggerSendsTheRevisionVerbatim`).
2. **Ignored revision with a build that never becomes stoppable**: the stop retries for 30 s of fake time, then reports "is building the newest commit" with `bam build cancel KEY`; nothing is written as `--last`. Pinned in Task 2.
3. **Ignored revision where the stop fails with something other than not found** (for example 405, stopping unsupported): no retry loop, immediate "is building the newest commit" error. Pinned in Task 2.
4. **`--revision` with `--json` and an ignored revision**: exit 5, nothing on stdout (the error goes to stderr as for any failed run). Pinned in Task 5.
5. **TUI: revision typed, then form closed with esc and reopened**: the row is empty again; a later run of another plan never inherits it. Pinned in Task 6.

`internal/app/run.go`:

```go
// Stopping a build whose revision Bamboo ignored: a build that was only just
// queued may have no job to stop yet, so a not-found answer is retried.
const (
	stopRetryEvery = 2 * time.Second
	stopRetryFor   = 30 * time.Second
)

// Run triggers the plan with the variables that differ from the plan's
// values and records the build as this repository's last build. When a
// revision was asked for and Bamboo ignored it, the build (which runs the
// newest commit) is stopped and Run fails.
func (s *Service) Run(ctx context.Context, ref PlanRef, vs VarSet) (provider.Build, error) {
	b, err := s.P.Trigger(ctx, provider.TriggerRequest{PlanKey: ref.PlanKey, Variables: vs.Changed(), Secret: vs.Secret(), Revision: ref.Revision})
	if err != nil {
		if ref.Revision != "" && b.Key != "" && errors.Is(err, errs.ErrUnsupported) {
			return b, s.stopIgnoredRevision(ctx, b.Key)
		}
		return provider.Build{}, err
	}
	rec := LastRecord{BuildKey: b.Key, Origin: s.Origin, PlanKey: ref.PlanKey, TriggeredAt: s.Clock.Now()}
	if ref.Target != nil {
		rec.Target = ref.Target.Name
	}
	// The build is already running; failing to remember it only loses --last.
	_ = s.State.SetLast(s.Cfg.RepoRoot, rec)
	return b, nil
}

// stopIgnoredRevision stops a build that runs the newest commit instead of
// the revision the user chose, and returns the error that says so.
func (s *Service) stopIgnoredRevision(ctx context.Context, key string) error {
	deadline := s.Clock.Now().Add(stopRetryFor)
	err := s.P.StopBuild(ctx, key)
	for err != nil && errors.Is(err, errs.ErrNotFound) && s.Clock.Now().Before(deadline) {
		select {
		case <-ctx.Done():
			err = ctx.Err()
		case <-s.Clock.After(stopRetryEvery):
			err = s.P.StopBuild(ctx, key)
		}
	}
	if err != nil {
		return errs.Bamboof("Bamboo ignored the revision; %s is building the newest commit", key).
			WithWhy("this Bamboo does not support building a chosen revision over REST").
			WithTry("bam build cancel " + key)
	}
	return errs.Bamboof("Bamboo ignored the revision; %s was stopped", key).
		WithWhy("this Bamboo does not support building a chosen revision over REST").
		WithTry("run without --revision, or use Run customised in Bamboo")
}
```

The fake clock's `After` advances `Now` by the wait, so 15 retries fill exactly 30 s: 1 immediate try + 15 = 16 calls. If `errs` is not yet imported in `run.go` it is (see the file header); `errors` is too.

// Queued prints the line after a trigger succeeds. Without a watch it says
// how to follow the build; with a revision, that the revision is checked
// only when the build starts.
func Queued(o Out, b provider.Build, watching bool, revision string) {
	fmt.Fprintf(o.W, "%s   %s   %s\n", style.Colored(o.Style, provider.StateSuccess, "✓ Queued"), o.Key(b.Key, b.URL), b.URL)
	switch {
	case watching:
	case revision != "":
		fmt.Fprintf(o.W, "  revision %s is checked when the build starts: bam watch %s\n", revision, b.Key)
	default:
		fmt.Fprintf(o.W, "  watch: bam watch %s\n", b.Key)
	}
}
